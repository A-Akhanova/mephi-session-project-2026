# Сессионный проект по безопасности GNU/Linux

Работа выполнена в отдельной ВМ без графической среды. Для проверки страницы использован номер `М265938`. Установленная конфигурация по `/etc/os-release` — `RED OS 8.0.3 (Standard Server Minimal)`. В исходном задании указана сертифицированная редакция.

| Раздел | Проверка | Артефакты |
| --- | --- | --- |
| Сеть | Настроены DHCP и имя `mephi-2026.domain.local`. `ping.out` подтверждает получение ответов от `8.8.8.8`. | `network.out`, `ping.out`, `hostname.out` |
| Пакеты | Система обновлена через DNF. Nginx и `libcap-ng-utils` установлены из репозитория. `tcpdump` скачан через DNF и установлен командой `rpm`. | `dnf.out`, `packages.out`, `tcpdump-4.99.5-1.red80.x86_64.rpm` |
| Диск | На втором диске создан раздел ext4 с меткой `MEPHI_WEB`. Автоматическое монтирование в `/mephi-web` проверено после перезагрузки. | `fstab`, `findmnt.out`, `lsblk.out` |
| Nginx и SELinux | Nginx включён для запуска при загрузке. SELinux работает в режиме Enforcing. Файлы из `/mephi-web` отдаются с контекстом `httpd_sys_content_t`. | `journalctl.out`, `nginx-state.out`, `getenforce.out`, `selinux-context.out` |
| Доступ | Разработчики `user1`, `user2`, `user3` с UID 5501–5503 могут читать и изменять проектные файлы. Кураторы из группы GID 4444 могут читать. Пользователь вне групп доступа не имеет. | `acl-test.out`, `passwd`, `group`, `stat.out` |
| Привилегии | `user1` проверил `tcpdump` на локальном loopback-трафике. У `tcpdump` назначена файловая привилегия `CAP_NET_RAW`. | `getcap.out`, `tcpdump.out` |
| Аутентификация | PAM допускает разработчиков и запрещает локальный вход кураторам. Срок действия пароля 90 дней, минимальная длина 12 символов. Поля паролей в копии `shadow` скрыты. | `pam-test.out`, `pam-login`, `pwquality.conf`, `shadow` |
| Проверка после перезагрузки | `curl http://localhost/` вернул `Hello from Student: М265938`. | `initial-boot.out`, `current-boot.out`, `curl.out`, `mephi-screenshot.png` |

`history.out` содержит команды настройки и проверки из трассировки Bash. Скриншот снят с консоли ВМ после перезагрузки на ядре `6.12.92-1.red80.x86_64`. При запуске обновлённого ядра возникла ошибка `systemd-udevd`, поэтому для стенда выбрано штатное предыдущее ядро. Обновление пакетов отражено в `dnf.out`.
